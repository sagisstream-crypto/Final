# VolScan Service — сканер Binance как отдельная программа

Это **не веб-страница**. Это служба, которая работает сама по себе: держит
соединение с Binance, считает сигналы, шлёт их в Telegram и пишет всё в базу.
Браузер нужен только чтобы **посмотреть** на результат — можно не открывать его
вообще, сканер от этого работать не перестанет.

Именно этим он отличается от старого `index.html`: там весь расчёт жил во
вкладке браузера, и стоило свернуть её на телефоне — соединение умирало, а
данные терялись. Здесь вкладка ни на что не влияет.

---

## Что он умеет

* Следит за **всеми** парами к USDT на споте и USDT-M фьючерсах Binance, у
  которых суточный оборот меньше **$500 000 000** (это практически весь рынок
  альткоинов).
* Считает: RVOL, минутные/двухминутные приросты объёма, аномалию объёма
  (z-оценка), 15-минутную структуру цены, поток тейкеров, часовой фон
  (RSI(14), ширина канала Боллинджера, `vol_z`) и составной **score 0-100**.
* Ловит **непрерывное ускорение** — пары, где цена и объём растут
  одновременно несколько минут подряд, а не дёргаются одним всплеском.
  Такие пары получают бейдж **🚀 УСКОРЕНИЕ** и поднимаются **в самый верх**
  списка.
* Шлёт в Telegram **лестницу из трёх сигналов** по одному событию, каждый
  сильнее предыдущего, вместо девяти одинаковых сообщений.
* Пишет каждый сигнал и цену через 5 / 15 / 30 / 60 / 240 минут после него в
  SQLite — чтобы потом можно было честно посчитать, сколько сработало.
* Показывает **один и тот же дашборд** на компьютере и на телефоне, с
  раскрытием любой пары в график цены и объёма.
* **Все фильтры и пороги правятся прямо из браузера или с телефона** — вкладка
  «⚙ ФИЛЬТРЫ», значение + кнопка OK, как в старом сканере, но настройки теперь
  живут на сервере и применяются к работающему движку сразу.

Замеренные на истории вероятности, ограничения и то, что **не** работает
(сжатие, накопление) — в [`../SIGNALS.md`](../SIGNALS.md). Прочитайте, там
честные цифры, а не реклама.

## Типы сигналов в Telegram

Каждое сообщение начинается с названия типа словами — глянул и сразу понятно,
что это:

| Сообщение | Что значит | Шлётся по умолчанию |
|---|---|---|
| **⚡ РАННИЙ ПРОБОЙ** | объём и цена только начали расти | да |
| **🚀 УСКОРЕНИЕ** | цена И объём растут непрерывно ~10 минут подряд | да |
| **🔥 АНОМАЛЬНЫЙ ВЫНОС — УСКОРЯЕТСЯ** | рост продолжает ускоряться, откатов нет | да |
| **🎯 КАНДИДАТ НА +10 %** | сетап, дававший на истории +10 % за 4 ч в 18.9 % случаев | да |
| **🔥 АНОМАЛЬНЫЙ ОБЪЁМ** | минутный оборот выбился из собственной нормы пары | нет |
| **🐋 НАКОПЛЕНИЕ** | цена стоит, но покупатели давят много минут подряд | нет |
| **😴→⚡ ВЫХОД ИЗ СЖАТИЯ** | пара стояла в коридоре и пошла вверх | нет |

Последние три по умолчанию выключены: на истории у них **нет** преимущества
над случайным входом, и включённые они дают десятки сообщений в день. В
дашборде они видны всегда. Включить — одна строка в конфиге (см. ниже).

**Почему сообщений мало.** У каждой пары в каждый момент может быть только
**один открытый эпизод**, и внутри эпизода в Telegram уходит только переход на
**более высокий** уровень. То есть ⚡ → 🚀 → 🔥, максимум три сообщения на одно
движение, и ни одного повтора. Сверх этого стоит жёсткий потолок **30
сообщений в час** на всё.

## Установка

### Что нужно заранее

* **Python 3.10 или новее** (проверялось на 3.11).
* Доступ в интернет к `binance.com` (в России может понадобиться VPN — сканер
  сам по себе ничего не обходит).
* ~200 МБ свободного места под базу (она сама чистит старое).

Проверить версию Python:

```bash
python3 --version
```

### Шаг 1. Распаковать и поставить зависимость

```bash
cd ~/volscan/scanner-service
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

На Windows вместо `source .venv/bin/activate` — `.venv\Scripts\activate`.

Зависимость ровно одна — `aiohttp`. Ничего больше ставить не надо.

### Шаг 2. Проверить, что всё собралось

```bash
python3 -m unittest discover -s tests
```

Должно вывести `OK` и 20 пройденных тестов. Если так — код рабочий.

### Шаг 3. Настроить Telegram

1. Откройте в Telegram [@BotFather](https://t.me/BotFather), команда
   `/newbot`, придумайте имя. BotFather выдаст **токен** вида
   `123456789:AAH...` — это `telegram_token`.
2. Создайте канал или группу, добавьте туда своего бота **администратором**
   (или просто напишите боту в личку `/start`).
3. Узнайте **chat id**: напишите что-нибудь в этот чат, затем откройте в
   браузере
   `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
   и найдите в ответе `"chat":{"id":-1001234567890`. Это `telegram_chat_id`
   (у каналов и групп он отрицательный — минус нужен).

Скопируйте пример конфига и впишите свои значения:

```bash
cp config.example.json config.json
nano config.json
```

```json
{
  "telegram_token": "123456789:AAH...ваш токен...",
  "telegram_chat_id": "-1001234567890",
  "max_initial_volume": 500000000,
  "max_initial_price": 0,
  "db_path": "volscan.db",
  "dashboard_host": "0.0.0.0",
  "dashboard_port": 8787,
  "alert_candidate": true,
  "alert_accumulation": false,
  "alert_anomaly": false,
  "log_level": "INFO"
}
```

`dashboard_host: "0.0.0.0"` означает «дашборд виден в локальной сети» — это
нужно, чтобы зайти с телефона. Если хотите только со своей машины — поставьте
`"127.0.0.1"`.

### Шаг 4. Запустить

```bash
python3 run.py --config config.json
```

Всё. В консоли пойдут строки вида
`VolScan service v17.0.0 — БД volscan.db, порог объёма $500,000,000`,
а в Telegram придёт сообщение «✅ VolScan сервис запущен».

Остановить — **Ctrl+C** (сервис корректно допишет базу и закроется).

## Как открыть дашборд

### На том же компьютере

```
http://localhost:8787
```

### С телефона, по домашнему Wi-Fi

1. Узнайте IP компьютера в локальной сети:
   * Linux / macOS: `ip addr | grep "inet "` или `ifconfig | grep "inet "`
   * Windows: `ipconfig` → строка «IPv4-адрес»
   Будет что-то вроде `192.168.1.42`.
2. Телефон должен быть в **той же** Wi-Fi сети.
3. В браузере телефона откройте `http://192.168.1.42:8787`

Если не открывается — почти всегда виноват firewall на компьютере:

```bash
# Linux (ufw)
sudo ufw allow 8787/tcp
```
На Windows при первом запуске система сама спросит — разрешите доступ для
частных сетей.

### С VPS / сервера

Просто `http://адрес-сервера:8787`. Если сервер смотрит в интернет —
**обязательно** закройте порт от посторонних: либо firewall'ом на свой IP,
либо поставьте перед ним nginx с паролем и HTTPS. Дашборд только читает,
но зачем показывать его всему миру.

### «На экран Домой» на телефоне

Теперь это **безопасно**. Телефон в новой схеме — просто экран: он не держит
соединение с Binance и ничего не считает. Ограничение из старого README
(«фон всё равно замрёт») к этой схеме больше не относится — считает сервер,
телефон только показывает. Свернули, выключили экран, вернулись через час —
на экране всё актуальное, а всё, что случилось за этот час, пришло в Telegram.

* **Android / Chrome:** меню ⋮ → «Добавить на главный экран».
* **iPhone / Safari:** «Поделиться» → «На экран «Домой»».

## Как пользоваться дашбордом

Интерфейс одинаковый на ПК и на телефоне — просто на узком экране колонки
перестраиваются, а кнопки становятся крупнее.

* Вкладки сверху: **ВСЕ / 🚀 УСКОРЕНИЕ / 🎯 КАНДИДАТЫ / 🐋 НАКОПЛЕНИЕ / 📜 СИГНАЛЫ**.
* Пары с ускорением всегда **наверху списка**, дальше по score.
* Бейджи у пары: 🚀 УСКОРЕНИЕ, 🎯 +10 %, 🐋 НАКОПЛ, ФОН (RSI<45 + широкий
  канал), СЖАТИЕ.
* **Нажмите на любую строку** — откроется карточка пары: все цифры, график
  цены (зелёная линия) и минутного оборота (столбцы) за последние 6 часов,
  оранжевым помечены минуты, когда горело ускорение, и вся история сигналов по
  этой паре с тем, насколько цена уходила вверх после каждого.
* Вкладка «СИГНАЛЫ» — общий журнал: что, когда, почему, ушло ли в Telegram.

Обновляется само раз в 3 секунды.

## Фильтры прямо из браузера (вкладка «⚙ ФИЛЬТРЫ»)

Та же логика, что была в старом сканере: у каждого параметра свой квадратик со
значением и кнопкой **OK** — нажали, применилось, ничего не перезагружается.
Галочки (вкл/выкл алерта) применяются сразу по клику.

**Важное отличие от старой версии.** Раньше фильтры лежали в `localStorage`
браузера: на телефоне были одни, на компьютере другие, и после очистки кэша всё
пропадало. Теперь настройки **серверные**: поменяли на телефоне — тут же
изменилось и на ПК, и, главное, в самом сканере. Значение применяется к
работающему движку **на следующем же тике** (доли секунды) и записывается в
SQLite, так что переживает перезапуск сервиса.

Можно писать сокращения, как раньше: `500m`, `3млн`, `50k`, `1 000 000`.

Параметры сгруппированы:

| Раздел | Что внутри |
|---|---|
| **Старые фильтры** | порог 10с $, порог Δ1м $, порог Δ2м $, макс. цена $, макс. нач. объём $, score ≥, лог score ≥, TG bot token, TG chat id |
| **🚀 Ускорение** | мин. рост за окно %, мин. RVOL, R² цены, R² объёма, дебаунс (сэмплов), окно (слотов), длина слота, порог score для отправки 🚀 в TG |
| **🎯 Кандидат +10%** | RVOL, Δ% за 5 мин, диапазон 15м / норма, расстояние до 24ч хая, позиция в 4ч диапазоне, доля покупок, кулдаун |
| **Алерты и Telegram** | какие типы уходят в Telegram (🎯 / 🔥 аномалия / 🐋 накопление / 😴→⚡ сжатие / ⭐ score), потолок сообщений в час, кулдаун и остывание эпизода, условия эскалации до 🔥 |
| **Остальные детекторы** | пороги аномалии объёма, накопления, сжатия и ⚡ раннего |

Два параметра (**окно** и **длина слота** детектора ускорения) сохраняются
сразу, но полностью подхватываются только после перезапуска — интерфейс об этом
честно пишет рядом с полем. Всё остальное работает мгновенно.

Некорректные значения не применяются: сканер отвечает по-русски, что именно не
так («R² цены ≥: допустимо от 0.0 до 1.0»), и поле подсвечивается красным.
Токен Telegram показывается замаскированным (`••••••••:AAA`) — если оставить
маску как есть и нажать OK, токен не изменится.

### Защита доступа (прочитайте, если дашборд виден в сети)

**По умолчанию защиты нет.** Это сделано осознанно: на домашнем компьютере,
где дашборд доступен только вам и вашему телефону по Wi-Fi, пароль — лишнее
трение. Но раз уж вы открыли порт в локальную сеть (или, тем более, наружу на
VPS), **любой, кто откроет этот адрес, сможет менять ваши пороги и увидеть
последние 4 символа токена Telegram**. Читать дашборд — не страшно, а вот
запись стоит закрыть.

Включается одной строкой в `config.json`:

```json
{
  "dashboard_token": "придумайте_длинную_строку"
}
```

После этого любая попытка изменить настройку без токена получает `403`.
В самом дашборде внизу вкладки «⚙ ФИЛЬТРЫ» есть поле **«токен этого браузера»** —
впишите туда ту же строку один раз, и он запомнится в этом браузере
(на телефоне — отдельно, один раз).

Что этот токен **не** делает: он не шифрует трафик и не закрывает просмотр.
Если сервис смотрит в интернет, полноценное решение — nginx перед ним с HTTPS и
basic-auth, либо вообще не открывать порт наружу, а ходить через VPN/SSH-туннель.
Токен здесь — защита от случайного соседа по Wi-Fi, а не от злоумышленника.

## Чтобы работало круглосуточно (systemd — основной путь)

Так сервис переживёт закрытие терминала, выход из системы и перезагрузку.

Создайте файл:

```bash
sudo nano /etc/systemd/system/volscan.service
```

Вставьте (поправьте `User` и пути под себя):

```ini
[Unit]
Description=VolScan Binance scanner service
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=youruser
WorkingDirectory=/home/youruser/volscan/scanner-service
ExecStart=/home/youruser/volscan/scanner-service/.venv/bin/python3 run.py --config config.json
Restart=always
RestartSec=10
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

Готовый файл лежит в `deploy/volscan.service` — можно скопировать и
отредактировать.

Команды (выучите эти пять, больше не понадобится):

```bash
sudo systemctl daemon-reload          # перечитать конфиг systemd
sudo systemctl enable --now volscan   # включить и запустить прямо сейчас
sudo systemctl status volscan         # посмотреть, жив ли
sudo systemctl restart volscan        # перезапустить (например, после правки config.json)
sudo systemctl stop volscan           # остановить
journalctl -u volscan -f              # смотреть логи в реальном времени
```

`Restart=always` значит, что если процесс упадёт — systemd поднимет его
через 10 секунд сам. `enable` значит, что он поднимется и после перезагрузки.

### Запасной вариант без systemd (nohup)

Если systemd нет (macOS, Windows+WSL, чужой хостинг):

```bash
cd ~/volscan/scanner-service
source .venv/bin/activate
nohup python3 run.py --config config.json > volscan.log 2>&1 &
echo $! > volscan.pid          # запомнить номер процесса
```

Посмотреть логи: `tail -f volscan.log`
Остановить: `kill $(cat volscan.pid)`

Минус: после перезагрузки компьютера запускать придётся руками.

## Аргументы командной строки

```
python3 run.py [--config config.json] [--db volscan.db] [--host 0.0.0.0]
               [--port 8787] [--no-dashboard] [--log-level INFO]
```

| Аргумент | Зачем |
|---|---|
| `--config` | путь к JSON-конфигу (по умолчанию `config.json`) |
| `--db` | другой файл базы (удобно для тестов) |
| `--host` | `0.0.0.0` — виден в сети, `127.0.0.1` — только локально |
| `--port` | порт дашборда |
| `--no-dashboard` | вообще не поднимать веб-морду (сканер работает как есть) |
| `--log-level` | `DEBUG` / `INFO` / `WARNING` |

Любую настройку можно задать и переменной окружения с приставкой `VOLSCAN_`,
например `VOLSCAN_TELEGRAM_TOKEN=... python3 run.py`.

## Главные настройки в `config.json`

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `max_initial_volume` | `500000000` | не брать пару, если её суточный оборот выше |
| `max_initial_price` | `0` | потолок цены; `0` = без ограничения |
| `score_threshold` | `60` | порог составной оценки |
| `accel_min_gain_pct` | `2.0` | сколько цена должна прибавить за окно ускорения |
| `accel_min_rvol` | `12` | минимальный RVOL для ускорения |
| `accel_persist` | `2` | сколько сэмплов подряд держать состояние (дебаунс) |
| `accel_alert_min_score` | `45` | ниже этого 🚀 пишется только в журнал, но не в Telegram |
| `tg_max_per_hour` | `30` | жёсткий потолок сообщений в час на всё |
| `dashboard_token` | `""` | пароль на изменение настроек через браузер; пусто = без защиты |
| `alert_candidate` | `true` | слать 🎯 КАНДИДАТ в Telegram |
| `alert_accumulation` | `false` | слать 🐋 НАКОПЛЕНИЕ (будет много, пользы не замерено) |
| `alert_anomaly` | `false` | слать 🔥 АНОМАЛЬНЫЙ ОБЪЁМ |
| `episode_cooldown_sec` | `7200` | не больше одного эпизода на пару за 2 часа |
| `flush_sec` | `10` | как часто скидывать накопленное в базу |

Всё это (кроме `db_path`, `dashboard_host`/`port` и `log_level`) правится и из
браузера, во вкладке «⚙ ФИЛЬТРЫ» — файл трогать не обязательно.

**Если сообщений слишком много** — поднимите `score_threshold` до 70 и
`accel_min_gain_pct` до 2.5. **Если слишком мало** — опустите
`score_threshold` до 55 и `accel_min_rvol` до 8. Влияние каждого порога на
долю попаданий — в таблицах `SIGNALS.md`.

## Проверка на истории (без живого рынка)

Можно прогнать реальные исторические минутные свечи через **тот же самый
движок** и посмотреть, что бы он выдал:

```bash
python3 tools/replay.py GENIUSUSDT 2026-09-14 2026-09-17
python3 tools/replay.py KSMUSDT 2026-09-06 2026-09-17 --market futures
```

Свечи качаются из официального архива Binance Vision. Пример вывода
(настоящий памп GENIUS/USDT, время UTC, у вас на скриншотах было UTC+5):


## Что делать, если что-то не так

| Симптом | Что проверить |
|---|---|
| `Connection refused` при открытии дашборда | сервис запущен? `sudo systemctl status volscan`. Порт тот? |
| С телефона не открывается, с ПК открывается | `dashboard_host` должен быть `0.0.0.0`; откройте порт в firewall; телефон в той же Wi-Fi |
| В логах `host_not_allowed` / `403` | до Binance нет доступа — VPN/прокси/страна |
| В Telegram ничего не приходит | токен и chat id в `config.json`; бот добавлен в чат админом; `chat_id` у групп с минусом |
| Слишком много сообщений | поднимите `score_threshold`, выключите `alert_candidate` |
| Таблица пустая | подождите 2-3 минуты: детекторам нужна минимум пара минут истории по паре |
| Настройка не сохраняется, «403» | включён `dashboard_token` — впишите его в поле «токен этого браузера» внизу вкладки ⚙ ФИЛЬТРЫ |
| Поменял окно/слот ускорения — не изменилось | эти два параметра подхватываются после `systemctl restart volscan` |
| Хочу сбросить всё к значениям из файла | остановите сервис и выполните `sqlite3 volscan.db "DELETE FROM settings;"` |
| Сервис перезапускается по кругу | `journalctl -u volscan -n 100` — там будет причина |
| База разрослась | она сама чистит раз в час (сэмплы 24 ч, сигналы 30 дней); можно просто удалить `volscan.db*` при остановленном сервисе |

## Где что лежит

```
scanner-service/
  run.py                  запуск
  config.example.json     пример конфига
  requirements.txt        зависимости (aiohttp)
  volscan/
    config.py             все пороги в одном месте
    indicators.py         математика (медианы, z-оценка, регрессии)
    engine.py             вся детекция и лестница алертов
    feed.py               websocket + REST fallback + часовой контекст
    storage.py            SQLite (WAL, пакетная запись)
    alerts.py             Telegram
    dashboard.py          адаптивный дашборд
    service.py            сборка всего вместе
  tools/replay.py         прогон истории через живой движок
  tests/                  офлайн-тесты
  deploy/volscan.service  готовый unit-файл systemd
```

База — один файл `volscan.db` (плюс `-wal` и `-shm` рядом). Скопировали эти
файлы — перенесли всю историю.

## Честное предупреждение

Всё, что сканер знает о вероятностях, получено **на исторических данных**.
В окружении, где он писался, живого доступа к Binance не было — сокеты
блокировались прокси. Логика проверена прогоном настоящих исторических свечей
через настоящий движок, но **боевого прогона в реальном времени не было**.

Первую неделю смотрите на него как на диагностику, а не как на торговый
сигнал. Сервис специально пишет в базу цену через 5/15/30/60/240 минут после
каждого сигнала — через пару недель у вас будет собственная статистика,
посчитанная на вашем рынке, а не на чужом прошлом.

**Даже лучший детектор здесь ошибается в 4 случаях из 5.** Это инструмент
внимания, а не инструмент входа. Не является финансовой рекомендацией.
