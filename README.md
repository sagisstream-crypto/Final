# VolScan Early v15 — телефонное PWA

Тот же сканер Binance, но как приложение на домашнем экране: без полной перезаписи базы на каждый тик, с IndexedDB и корректным выходом в фон.

## Фикс: таблица пропадала на реальном деплое

После добавления панелей «🎯 Пороговый сигнал» / «🪤 Тихая полка» / «📐 План
сделки» и кучи новых полей ввода (пороги, score, стоп/цель, telegram) шапка
страницы на невысоких окнах браузера стала выше самого окна — из-за
`overflow: hidden` у области таблицы это схлопывало её в невидимую полоску
(«таблица не открывается»), особенно на брейкпоинте с нижними вкладками
(≤900px).

Исправлено: все фильтры/пороги/панели теперь спрятаны за кнопку **«⚙
Фильтры»** в правом углу шапки, свёрнуты по умолчанию — при заходе таблица
сразу занимает весь экран. При раскрытии панель фильтров сама скроллится и
не толкает таблицу за пределы экрана (проверено на 1366×768 и на телефонном
390×844 — таблица остаётся видна и листается в обоих случаях, до и после
раскрытия фильтров).

## Что исправлено относительно HTML v15

- Состояние пишется в **IndexedDB**, не в `localStorage` на каждый тик. Раньше `JSON.stringify` всего рынка раз в секунду вешал телефон.
- Сохранение раз в 8–12 секунд и сразу при сворачивании / `pagehide` / `freeze`.
- Пока экран свёрнут, таблица не перерисовывается.
- Сокеты сами закрываются в фоне (иначе iOS/Android оставляют полумёртвые соединения) и поднимаются при возврате. База пар, алерты, пороги, score — на месте.
- Запрос **persistent storage**, чтобы система реже вычищала данные.
- Нижние вкладки «Таблица / Сигналы», крупные кнопки, `font-size: 16px` в инпутах (без зума iOS).
- Service Worker кэширует только оболочку. Котировки Binance не кэшируются.

## SCORE: реальный вынос против шпильки на объёме

Разбор двух пар с малым 24ч объёмом (MYXUSDT, EVAAUSDT) показал, что размер
самого объёмного всплеска сам по себе не отличает вынос от шпильки — меньший
по объёму импульс EVAA продолжился сильнее, чем больший по объёму импульс MYX.
Из этого разбора в SCORE (`computeScore()` в `index.html`) добавлено:

- **Доля тейкер-покупок теперь считается и на USDT-M фьючерсах.** «Горячий»
  `kline_1m`-поток раньше открывался только на spot-хосте и брал только
  строки `market === "SPOT"` — фьючерсные пары никогда не получали тейкер-долю
  в SCORE. Плюс к тому, 12-месячный прогон (см. ниже) показал, что сам признак
  почти не отличает вынос от слива — вес у него теперь маленький, это скорее
  тай-брейкер, чем сигнал.
- **Форма последней 1m свечи горячего потока — усилена.** Закрытие близко к
  максимуму свечи с широким телом и маленькой верхней тенью — плюс к SCORE
  (подтверждение, что пробитый уровень удержали); закрытие в нижней части
  диапазона с длинной верхней тенью — минус (классическая форма «прокол и
  откат», как на MYX). Это самый устойчивый признак во всём 12-месячном
  прогоне, вес увеличен.
- **«Тихая полка» перед выносом — вес сильно снижен.** На полном годе признак
  оказался шумным и нестабильным (на одном куске времени в плюс к выносу, на
  другом в минус) — оставлен как маленький тай-брейкер, не как уверенный бонус.

Статистическое исследование (эффект-сайз по признакам, условные частоты,
потрейдовый бэктест с комиссией/стопом/целью) — в
[`research/binance_pump_patterns/`](research/binance_pump_patterns/README.md).
Ему нужен реальный доступ в интернет к архиву Binance, поэтому запускается
локально, а не в этой репе. Веса SCORE выше откалиброваны по 12-месячному
прогону оттуда (267 событий).

## 📐 План сделки — стратегия из бэктеста, встроенная в сканер

На каждый ⭐ SCORE-сигнал сканер сам заводит виртуальную позицию по правилам,
провалидированным в 12-месячном бэктесте: стоп −8%, цель +16%, тайм-аут 2 часа
(все три числа настраиваются в UI), риск 1% виртуального капитала на сделку,
комиссия 0.10% за круг. Дальше сканер сам следит за ценой и закрывает позицию
по стопу/цели/времени — без участия пользователя. Не более одной открытой
позиции на пару. Панель «📐 ПЛАН СДЕЛКИ» показывает открытые позиции (вход,
стоп, цель, текущий floating %, время до тайм-аута) и журнал закрытых сделок
(тип выхода, % и R), плюс сводку: виртуальный капитал, число сделок, win-rate.

Это **не автоторговля** — сканер не отправляет ордера на биржу, только считает
виртуальный P&L теми же правилами, что тестировались на истории, чтобы честно
показывать, отработал бы сигнал или нет. Кнопка «📐 ПЛАН СДЕЛКИ: ВКЛ/ВЫКЛ»
выключает создание новых позиций (уже открытые продолжают отслеживаться).

## 🎯 Пороговый сигнал — отдельная лента наверху + Telegram

Пять «пороговых» сигналов — SPIKE (10с), **SPIKE30 (30с, новое)**, VEL1M/VEL2M
(объём за 1/2 минуты), ACCEL (наклон за 90с) — каждый со своим $ порогом в
шапке. Раньше они только пищали и слали браузерное уведомление, а в «🔔 ЖУРНАЛ
СИГНАЛОВ» внизу ничего не появлялось (эта запись была отключена отдельным
решением ранее). Теперь у них есть свой независимый пришпиленный список
**«🎯 ПОРОГОВЫЙ СИГНАЛ»** в самом верху страницы — последние 30 срабатываний,
клик по строке ведёт к паре в таблице.

Эти же пять сигналов можно продублировать в Telegram: вписать токен бота (его
выдаёт [@BotFather](https://t.me/BotFather)) и chat_id в поле «telegram bot
token / chat id», нажать **ТЕСТ** — если тестовое сообщение дошло, рассылка
включается сама. Токен и chat_id хранятся только локально (IndexedDB в этом
браузере), уходят только в `api.telegram.org`, больше никуда.

**Проверено вручную (headless-браузер, реальный код сканера, не имитация):**
подставил истории объёма задним числом и прогнал через настоящий
`handleTickerBatch()` — все пять порогов (SPIKE/SPIKE30/VEL1M/VEL2M/ACCEL)
действительно срабатывают, когда цифры превышают порог, кулдаун не даёт
сработать второй раз подряд на том же тике, а `sendTelegram()` формирует
корректный POST на `api.telegram.org/bot<token>/sendMessage` с нужным телом.
Сама доставка в Telegram с телефона проверяется только на реальном токене —
из этой среды разработки исходящая сеть на `api.telegram.org` заблокирована
политикой (как и Binance), поэтому доехать до настоящего Telegram-сервера
отсюда я не могу — но код гарантированно отправляет правильный запрос.

## Честный лимит фона

Ни один браузер на телефоне не даст живому WebSocket к Binance работать часами в фоне. iOS убивает JS через секунды после сворачивания.

Приложение делает максимум возможного:

1. Перед уходом сбрасывает базу на диск.
2. Не теряет пары, сигналы, пороги, журнал.
3. При открытии заново поднимает сокеты и продолжает сессию.

Пока телефон свёрнут, **новые** тики не приходят. Для круглосуточного фона нужен нативный Android Foreground Service (Capacitor) — это уже отдельная обёртка.

## Деплой на Cloudflare Pages

Самый быстрый способ получить https-адрес для установки на телефон.

**Вариант A — через GitHub (автодеплой на каждый push, рекомендуется):**

1. [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Выбрать репозиторий `sagisstream-crypto/Final`, ветку — эту (`claude/binance-futures-pump-patterns-cbvvfk`) или `main`, если ветку смёржили.
3. Build settings: **Framework preset — None**, **Build command — оставить пустым**, **Build output directory — `/`** (корень репозитория, здесь нет отдельной папки сборки).
4. **Save and Deploy**. Через ~30 секунд будет ссылка вида `https://final-xxx.pages.dev` — это готовый https-хостинг, ничего больше не нужно.
5. Дальше каждый `git push` в подключённую ветку сам передеплоит сайт.

**Вариант B — перетащить папку (без GitHub, разово):**

1. **Workers & Pages** → **Create** → **Pages** → **Upload assets**.
2. Перетащить в окно файлы `index.html`, `manifest.json`, `sw.js`, `_headers` и папку `icons/` (со всей структурой, не только содержимое) — все вместе, одним заходом.
3. **Deploy site** → получаете `https://....pages.dev`.

`_headers` в корне репозитория уже настроен так, что Cloudflare не закэширует `sw.js`/`manifest.json`/`index.html` на CDN надолго — иначе после обновления сайта телефон мог бы ещё долго открывать старую версию из кэша.

## Установка на телефон

Нужен https-хостинг (Cloudflare Pages — см. выше, либо GitHub Pages, либо любой nginx с SSL). `file://` PWA не ставится.

### Android (Chrome)

1. Откройте `index.html` по https.
2. Меню → **Установить приложение** / «На экран Домой».
3. В настройках батареи для VolScan: **без ограничений**.
4. В приложении включите **Не гасить экран**, если держите его открытым как терминал.

### iPhone (Safari)

1. Поделиться → **На экран Домой**.
2. Открывать ярлык, не вкладку Safari.
3. Фон всё равно будет замирать — это ограничение iOS, не бага сканера.

## Локальный запуск

```bash
cd volume-scanner-pwa
python3 -m http.server 8080
```

На телефоне в той же Wi‑Fi сети: `http://IP:8080`. Для установки PWA всё равно лучше https.

## Capacitor (если нужен APK)

```bash
npm create @capacitor/app
# скопировать содержимое этой папки в www/
npx cap add android
npx cap sync
```

Добавьте Foreground Service плагин, если хотите тики в фоне на Android. iOS background WS так не получить.
