# VolScan Early v15 — телефонное PWA

Тот же сканер Binance, но как приложение на домашнем экране: без полной перезаписи базы на каждый тик, с IndexedDB и корректным выходом в фон.

## Что исправлено относительно HTML v15

- Состояние пишется в **IndexedDB**, не в `localStorage` на каждый тик. Раньше `JSON.stringify` всего рынка раз в секунду вешал телефон.
- Сохранение раз в 8–12 секунд и сразу при сворачивании / `pagehide` / `freeze`.
- Пока экран свёрнут, таблица не перерисовывается.
- Сокеты сами закрываются в фоне (иначе iOS/Android оставляют полумёртвые соединения) и поднимаются при возврате. База пар, алерты, пороги, score — на месте.
- Запрос **persistent storage**, чтобы система реже вычищала данные.
- Нижние вкладки «Таблица / Сигналы», крупные кнопки, `font-size: 16px` в инпутах (без зума iOS).
- Service Worker кэширует только оболочку. Котировки Binance не кэшируются.

## Честный лимит фона

Ни один браузер на телефоне не даст живому WebSocket к Binance работать часами в фоне. iOS убивает JS через секунды после сворачивания.

Приложение делает максимум возможного:

1. Перед уходом сбрасывает базу на диск.
2. Не теряет пары, сигналы, пороги, журнал.
3. При открытии заново поднимает сокеты и продолжает сессию.

Пока телефон свёрнут, **новые** тики не приходят. Для круглосуточного фона нужен нативный Android Foreground Service (Capacitor) — это уже отдельная обёртка.

## Установка на телефон

Нужен https-хостинг (GitHub Pages, Cloudflare Pages, любой nginx с SSL). `file://` PWA не ставится.

### Android (Chrome)

1. Откройте `index.html` по https.
2. Меню → **Установить приложение** / «На экран Домой».
3. В настройках батареи для VolScan: **без ограничений**.
4. В приложении включите **Не гасить экран**, если держите его открытым как терминал.

### iPhone (Safari)

1. Поделиться → **На экран Домой**.
2. Открывать ярлык, не вкладку Safari.
3. Фон всё равно будет замирать — это ограничение iOS, не бага сканера.

## Локальный запуск

```bash
cd volume-scanner-pwa
python3 -m http.server 8080
```

На телефоне в той же Wi‑Fi сети: `http://IP:8080`. Для установки PWA всё равно лучше https.

## Capacitor (если нужен APK)

```bash
npm create @capacitor/app
# скопировать содержимое этой папки в www/
npx cap add android
npx cap sync
```

Добавьте Foreground Service плагин, если хотите тики в фоне на Android. iOS background WS так не получить.

## 🧭 v16 — «Полка → пробой»: сканер, проверенный на истории

Отдельный модуль (панель под «🪤 ТИХАЯ ПОЛКА» в шапке), который ищет ровно
то движение, что на скриншотах ALCHUSDT/AGTUSDT: долгая тихая консолидация
и резкий вынос с объёмом. В отличие от старой «тихой полки» (которая судит
только по объёму тикера за последние ~20 минут), этот модуль:

1. Раз в 15 минут, сразу после закрытия свечи, тянет исторические 15-минутные
   свечи (`fapi.binance.com/fapi/v1/klines`) по топ-N USDT-M фьючерсам (по
   обороту за 24ч, N настраивается, по умолчанию 120).
2. Считает диапазон цены и объём за последние W баров («полка») и сравнивает
   последнюю закрытую свечу с границами этой полки («пробой»).
3. Сигнал показывается только когда полка **и** пробой одновременно проходят
   один из двух порогов — они не придуманы на глаз, а подобраны бэктестом.

### Методика бэктеста

- Данные: официальный архив Binance (`data.binance.vision`), 15-минутные
  свечи, **97 ликвидных вечных USDT-M фьючерсов**, непрерывный год
  (по 12 месяцев на конец сбора данных), ≈3.4 млн свечей.
- «Полка» = W баров подряд, где `(макс−мин)/средняя_цена ≤ C%`.
- «Пробой» = следующий бар закрывается за пределами полки минимум на `DIST%`,
  объём этого бара ≥ `SPIKE×` средней за полку.
- «Успех» (реальный, не шумовой вынос) = в следующие 3 часа (12 баров) цена
  уходит в пользу сигнала на ≥1.5%, и это как минимум в 1.5 раза больше
  максимальной просадки за то же время — то есть не откатывается сразу же
  обратно в полку.
- Без всякого фильтра (случайный бар) доля «успехов» ≈ **20%** — это шумовой
  пол, с которым сравнивается любой фильтр.

### Что нашлось

- Проверка объёма и величины пробоя **без** требования узкого диапазона почти
  не поднимает точность (~20 → ~36%) — то есть «эти два фильтра одни»
  недостаточны.
- Сжатие диапазона реально работает как фильтр шума, только когда оно
  **строгое**: диапазон ≤1.5% за 6 часов поднимает точность с ~36% до **~47%**
  на тех же порогах пробоя/объёма — почти вдвое лучше случайного уровня, но
  такое сочетание редкое (≈1 раз в 1.5 года на пару).
- Отдельный фильтр «объём стих перед пробоем» (сравнение объёма полки с более
  длинной базой) почти не добавляет точности сверх самого сжатия диапазона —
  поэтому в боевой логике его нет, только диапазон + пробой + объём пробойного
  бара.
- Итоговый баланс «поймать максимум реальных выносов, а не просто максимум
  сигналов» — два уровня:

  | Тир | Полка | Диапазон | Пробой | Объём | Точность | Частота (97 пар / год) |
  |---|---|---|---|---|---|---|
  | **СТАНДАРТ** | ≥3ч (12×15м) | ≤4% | ≥1% | ≥2× | ~34% (×1.7 к случайности) | ~2300 сигналов |
  | **СИЛЬНЫЙ** | ≥6ч (24×15м) | ≤1.5% | ≥1.5% | ≥5× | ~47% (×2.35 к случайности) | ~80 сигналов |

  Средний ход в пользу сигнала — +2–2.4% за 3 часа; если сигнал не
  срабатывает, откат сопоставимого размера (~1.8–2.3%) — стоп стоит ставить
  примерно на уровне цели, а не «в разы уже».

Скрипты бэктеста (скачивание данных, сам бэктест, проверка на устойчивость
и абляции) не входят в PWA — это разовый офлайн-анализ, а в `index.html`
зашиты только его выводы (константы `SB_STD` / `SB_STRONG` в блоке
«v16 — ПОЛКА → ПРОБОЙ» в скрипте).

### Telegram-уведомления

В панели «🧭 ПОЛКА → ПРОБОЙ»:

1. Включите **СКАНЕР** — начнётся отслеживание топ-N фьючерсов.
2. Впишите **bot token** (получить у [@BotFather](https://t.me/BotFather)) и
   **chat id** (свой numeric id, например от [@userinfobot](https://t.me/userinfobot),
   или id группы/канала, куда бот добавлен админом) → «Сохранить».
3. Нажмите **Тест** — должно прийти тестовое сообщение.
4. Включите **TELEGRAM: ВКЛ** — теперь каждый сигнал СТАНДАРТ/СИЛЬНЫЙ
   уходит в чат с направлением (лонг/шорт), тиром, score, диапазоном полки,
   силой пробоя и объёмом.

Токен и chat id хранятся только в `localStorage` этого браузера, никуда
кроме `api.telegram.org` не отправляются. Это разведочный инструмент, не
торговый сигнал «в слепую» — решение о входе/риске всегда за вами.
