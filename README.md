# VolScan Early v15 — телефонное PWA

Тот же сканер Binance, но как приложение на домашнем экране: без полной перезаписи базы на каждый тик, с IndexedDB и корректным выходом в фон.

## Что исправлено относительно HTML v15

- Состояние пишется в **IndexedDB**, не в `localStorage` на каждый тик. Раньше `JSON.stringify` всего рынка раз в секунду вешал телефон.
- Сохранение раз в 8–12 секунд и сразу при сворачивании / `pagehide` / `freeze`.
- Пока экран свёрнут, таблица не перерисовывается.
- Сокеты сами закрываются в фоне (иначе iOS/Android оставляют полумёртвые соединения) и поднимаются при возврате. База пар, алерты, пороги, score — на месте.
- Запрос **persistent storage**, чтобы система реже вычищала данные.
- Нижние вкладки «Таблица / Сигналы», крупные кнопки, `font-size: 16px` в инпутах (без зума iOS).
- Service Worker кэширует только оболочку. Котировки Binance не кэшируются.

## Честный лимит фона

Ни один браузер на телефоне не даст живому WebSocket к Binance работать часами в фоне. iOS убивает JS через секунды после сворачивания.

Приложение делает максимум возможного:

1. Перед уходом сбрасывает базу на диск.
2. Не теряет пары, сигналы, пороги, журнал.
3. При открытии заново поднимает сокеты и продолжает сессию.

Пока телефон свёрнут, **новые** тики не приходят. Для круглосуточного фона нужен нативный Android Foreground Service (Capacitor) — это уже отдельная обёртка.

## Установка на телефон

Нужен https-хостинг (GitHub Pages, Cloudflare Pages, любой nginx с SSL). `file://` PWA не ставится.

### Android (Chrome)

1. Откройте `index.html` по https.
2. Меню → **Установить приложение** / «На экран Домой».
3. В настройках батареи для VolScan: **без ограничений**.
4. В приложении включите **Не гасить экран**, если держите его открытым как терминал.

### iPhone (Safari)

1. Поделиться → **На экран Домой**.
2. Открывать ярлык, не вкладку Safari.
3. Фон всё равно будет замирать — это ограничение iOS, не бага сканера.

## Локальный запуск

```bash
cd volume-scanner-pwa
python3 -m http.server 8080
```

На телефоне в той же Wi‑Fi сети: `http://IP:8080`. Для установки PWA всё равно лучше https.

## Capacitor (если нужен APK)

```bash
npm create @capacitor/app
# скопировать содержимое этой папки в www/
npx cap add android
npx cap sync
```

Добавьте Foreground Service плагин, если хотите тики в фоне на Android. iOS background WS так не получить.

## 🧪 Бэктест (вкладка «БЭКТЕСТ»)

Пороги в шапке (Δ1м, Δ2м, score, цена, объём) раньше подбирались на глаз. Вкладка «БЭКТЕСТ» прогоняет
**ту же самую логику сигналов** по историческим минутным свечам Binance и показывает, что было с ценой
после каждого сигнала.

### Как это устроено

1. **Выборка.** Сутки берутся равномерно по последнему году (стратифицированная выборка: 12 / 26 / 52 суток).
   Внутри суток берутся все пары, которые накануне подходили под фильтр шапки (цена < $10, объём 24ч ≤ $3M),
   с воспроизводимой случайной подвыборкой до N пар — поэтому частоты и проценты несмещённые.
2. **Прогон.** На каждую пара-сутки грузится окно 3000 минут: сутки прогрева (скользящие 24ч объём, VWAP,
   хай/лоу, baseline «тихой полки»), тестируемые сутки и 120 минут вперёд для замера исхода.
   Признаки считаются ровно как в живом сканере: RVOL, Δ% за 1м, средний чек сделки против своей медианы,
   положение в дневном диапазоне, отклонение от VWAP, доля тейкер-покупок, пробой 24ч хая, выход из тихой полки.
   `score` считает **та же функция `computeScore`**, что и в живом режиме.
3. **Перебор.** Один проход сохраняет все минуты-кандидаты со всеми признаками и исходами (MFE/MAE за 15/60/120 мин).
   После этого любая комбинация порогов — это фильтр по готовой таблице, поэтому «перепробовать все настройки»
   считается за секунды, без повторной загрузки. Таблица событий лежит в IndexedDB: «ПЕРЕСЧИТАТЬ ОТЧЁТ»
   работает уже без сети.

### Что в отчёте

* сетка **score × порог Δ1м** — отдельно по доле выносов и по доле движений 10%+;
* сравнение типов сигналов (SCORE / VEL1M / VEL2M / ACCEL / QUIET) при разных порогах;
* срезы по каждому признаку (score, RVOL, Δ%1м, тейкер, чек сделки, объём пары, цена, диапазон, VWAP,
  тихая полка, новый хай, час UTC) — видно, что реально предсказывает вынос, а что только шумит;
* **идеальные пороги** — координатный поиск отдельно под «выносы» и под «10%+»;
* топ конфигураций и кнопки `CSV СОБЫТИЙ` / `СКОПИРОВАТЬ ИТОГ`.

Чтобы конфигурация с пятью удачными сигналами не побеждала конфигурацию с четырьмя сотнями, ранжирование
идёт по нижней границе доли (интервал Уилсона, 95%), и есть жёсткий минимум наблюдений.

### Чего бэктест не знает

* Минутные свечи не показывают 10-секундные окна, поэтому **порог 10с (SPIKE)** напрямую не тестируется:
  его верхняя граница — строка VEL1M с тем же значением.
* **Стакана и спреда** в истории нет. В `score` они дают от −10 до +10, поэтому здешний score примерно
  на 5 пунктов ниже живого — пороги надёжнее сравнивать по частоте сигналов в день, а не по абсолютной цифре.
* Тейкер-доля в бэктесте есть по всем парам, в приложении — только по 12 горячим.
* В выборке только пары, торгующиеся сегодня: делистнутые за год не попали (смещение в оптимистичную сторону).
* Вход считается по закрытию сигнальной минуты, MFE/MAE — по максимуму/минимуму следующих минут.
  Комиссия и проскальзывание не учтены.

### Нагрузка

Быстрый прогон — около 1.1к запросов к Binance (3–6 минут), средний — 4.7к, год целиком — около 19к запросов
(50–90 минут). Темп ограничен встроенным лимитером (429/418 обрабатываются с паузой). На время загрузки
живой поток ставится на паузу, прогон можно прервать кнопкой «СТОП» — собранное сохранится.
