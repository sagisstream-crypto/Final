# onchain-radar

Ончейн-сканер накопления по ERC-20 токенам: следит за net-flow с бирж, DEX
buy/sell и повторными покупками крупных кошельков, комбинирует это в score
0–100 и шлёт карточку сигнала (консоль + опционально Telegram-бот), когда
несколько независимых признаков совпадают. Плюс **бэктест**, который честно
проверяет на исторических данных, действительно ли эти признаки предшествуют
росту цены — а не просто звучат правдоподобно.

Не клон конкретного платного продукта — независимая реализация того же
класса сигнала (ончейн-накопление до движения цены) на публичных бесплатных
источниках: [Etherscan V2 API](https://docs.etherscan.io/etherscan-v2) для
переводов токена/балансов, [DexScreener](https://docs.dexscreener.com/api/reference)
для цены/ликвидности/DEX-объёма и [CoinGecko](https://docs.coingecko.com/reference/contract-address)
для исторических цен (только для бэктеста).

## Важно: чего тут нет

- **"Smart Money"-разметки кошельков нет.** Платные сервисы вроде Arkham
  ($1500/мес за нужный уровень API) продают проприетарные ярлыки "кошелёк с
  историей удачных ранних входов". Здесь вместо этого — прозрачная эвристика:
  крупные переводы (≥ `largeTransferUsdMin`, по умолчанию $5000) на адреса,
  которые не являются известной биржей/пулом, плюс повторные покупки одним
  адресом в окне.
- **Адреса бирж вы вписываете сами.** `src/knownExchangeWallets.js` — пустой
  каркас. Не стал подставлять адреса горячих кошельков бирж по памяти: одна
  ошибка в hex-адресе даёт тихо неверный сигнал, а не сигнал послабее. Берите
  адреса из проверяемого источника (ярлык прямо на etherscan.io/arbiscan.io,
  публичный reference-список, Nansen/Arkham entity pages) — формат см. в файле.
- **Live-интеграция и бэктест не проверены в этой среде.** `api.etherscan.io`,
  `api.dexscreener.com` и `api.coingecko.com` заблокированы политикой
  egress-прокси текущей песочницы (то же самое, что не пускает и на `t.me`) —
  проверить реальные HTTP-запросы отсюда не вышло. Проверена только чистая
  логика (`npm test`, 12/12 зелёных на синтетических данных). Запускайте на
  машине с обычным доступом в интернет и смотрите на первые прогоны глазами.
- **Это не финансовый совет и не гарантия.** Даже если бэктест покажет
  положительную корреляцию на вашей выборке токенов — это статистика по
  прошлому на небольшом наборе данных, а не предсказание будущего.

## Шаг 1. Установка

Нужен Node.js 20+ (проверить: `node -v`). Внешних npm-зависимостей нет —
`npm install` не нужен.

```bash
cd onchain-radar
cp .env.example .env
```

## Шаг 2. Получить бесплатный API-ключ Etherscan

1. Зарегистрируйтесь на https://etherscan.io/register (email + пароль, без карты).
2. Зайдите в https://etherscan.io/myapikey → "Add" → скопируйте ключ.
3. Вставьте его в `.env`: `ETHERSCAN_API_KEY=ваш_ключ`.

Один ключ работает сразу на Ethereum, Arbitrum и остальных поддерживаемых
EVM-сетях через Etherscan V2 (`chainid` в запросе) — отдельный ключ на
каждую сеть не нужен.

## Шаг 3. Заполнить вотчлист

В `.env`, `WATCHLIST` — список токенов через запятую в формате
`chainId:0xАдресКонтракта` (chainId: 1 = Ethereum, 42161 = Arbitrum, полный
список — `src/chains.js`). Пример на $UNI и $ARB уже стоит в `.env.example`.

Адрес контракта берётся со страницы токена на coinmarketcap.com/coingecko.com
(раздел "Contract") или прямо с etherscan.io/token/...

## Шаг 4. Вписать адреса бирж (иначе net-flow всегда будет нулевым)

Откройте `src/knownExchangeWallets.js`, впишите адреса горячих кошельков
нужных вам бирж по инструкции в комментарии файла (кошельки берите с
etherscan.io/arbiscan.io — у размеченных адресов есть публичный ярлык
"Exchange" — или с проверяемого reference-списка). Без этого шага сигнал
"вывод/занос на биржи" не будет работать — придёт всегда 0.

## Шаг 5. Живой сканер

```bash
npm start
```

Опрашивает `WATCHLIST` каждые `POLL_INTERVAL_MS` (по умолчанию 5 мин),
печатает карточку в консоль и дописывает `data/signals.jsonl`, когда score
токена проходит порог (`SCORE_ALERT_THRESHOLD` = 55 в `src/alerts.js`) и
токен не в кулдауне (6ч — это ончейн-накопление, не минутный скальп).
Остановить — `Ctrl+C`.

Хотите карточки в Telegram — создайте бота через
[@BotFather](https://t.me/BotFather) (`/newbot`, скопируйте токен), узнайте
свой `chat_id` через [@userinfobot](https://t.me/userinfobot), впишите оба
значения в `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) и перезапустите.

## Шаг 6. Бэктест — проверить, работает ли это вообще

```bash
npm run backtest
```

Для каждого токена из `WATCHLIST` берёт точки в прошлом (раз в
`BACKTEST_SAMPLE_INTERVAL_DAYS` дней за последние `BACKTEST_PERIOD_DAYS`,
по умолчанию 90/7 — то есть ~12 точек на токен), в каждой точке честно
воссоздаёт метрики накопления **только по данным, доступным до этой даты**
(так же, как если бы сканер уже тогда работал), и сравнивает с тем, что
реально произошло с ценой через 7/14/30 дней (`BACKTEST_FORWARD_DAYS`).

На выходе — в консоль и в `data/backtest-samples.json` (сырые точки, можно
открыть и посмотреть руками) и печатается сводка вида:

```
Корреляция метрики (в момент сэмплирования) с forward-доходностью:
  +7д: net-flow ratio r=0.14 · крупных кошельков r=0.31 · повторных покупок r=0.08 · новых держателей r=0.19
  ...

Группа "похоже на накопление" (net-flow > 0 И крупных кошельков >= 3) vs остальное:
  +7д — сигнал (n=18): win rate +61.1%, средняя доходность +4.2%, медиана +1.8%
         без сигнала (n=42): win rate +47.6%, средняя доходность +0.3%, медиана -0.5%
```

Как читать:
- **r (корреляция)** от -1 до 1. Около 0 — метрика не связана с forward-доходностью
  на вашей выборке. Ближе к 1 — чем сильнее метрика, тем выше была доходность.
  Ниже 0.2–0.3 по модулю обычно значит "слабая или никакая связь", даже если
  знак "правильный".
- **win rate сигнал vs без сигнала** — если у группы "похоже на накопление"
  win rate и средняя доходность заметно выше, чем у остальных точек, метрика
  что-то ловит. Если почти одинаково (или хуже!) — на ваших токенах это не
  работает, что бы ни обещала реклама.
- **n (число точек)** — меньше ~30–50 суммарно по всем токенам доверять
  выводам рано, это просто прикидка, а не статистически значимый результат.
  Расширьте `WATCHLIST` и/или `BACKTEST_PERIOD_DAYS`, чтобы точек стало больше.

### Что бэктестится, а что нет

DexScreener не отдаёт историю (только текущее состояние пары), поэтому в
бэктесте **нет** DEX buy/sell ratio и нормировки на ликвидность, которые
есть в живом score (`src/score.js` → `computeAccumulationScore`). Бэктестятся
только компоненты, честно восстановимые из истории Etherscan: net exchange
flow, число крупных кошельков, повторные покупки, новые крупные держатели.
Значит, число из `npm start` (0–100 score) и то, что проверяет бэктест — это
пересекающиеся, но не идентичные вещи. Если хотите проверить именно то, что
видите вживую, — используйте вывод бэктеста как индикатор направления
("вывод с бирж + много кошельков в среднем работает или нет"), а не как
точную репродукцию live score.

Проверка исторических данных также ограничена free-тирами: Etherscan
(~5 запросов/с — бэктест сам троттлит) и CoinGecko (жёсткий лимит free API,
скрипт держит паузу ~2.5с между запросами; при 429-ошибке просто перезапустите
`npm run backtest` — он не хранит прогресс между запусками, но и не портит
уже посчитанное, каждый запуск независимый). На watchlist из 5-10 токенов
с настройками по умолчанию прогон занимает несколько минут.

## Тесты

```bash
npm test
```

Только чистая логика — без сети:
- `src/score.js` (`analyzeTransfers`, `computeAccumulationScore`) — тест `test/score.test.js`.
- `src/backtestStats.js` (`pearsonCorrelation`, `compareBySignal`) — тест `test/backtestStats.test.js`.

## Как это устроено

1. `src/watcher.js` (live) берёт лучшую по ликвидности DEX-пару токена
   (DexScreener) и последние ~200 ERC-20 Transfer-событий по контракту
   (Etherscan).
2. `src/backtest.js` (история) вместо "последних N" берёт переводы за
   конкретное окно блоков в прошлом (`fetchTokenTransfersInRange` +
   `fetchBlockNumberByTimestamp` в `src/providers/etherscanClient.js`) и цену
   на нужную дату из `src/providers/coingeckoClient.js`.
3. `src/score.js` — общая для обоих путей логика: размечает переводы
   (вывод/занос на известные биржи, крупные переводы на новые/повторные
   некэксчейндж-адреса) и считает 0–100 score с разбивкой по причинам (тот
   же принцип, что `computeScore()` в `../index.html`: сумма взвешенных
   компонентов, зажатая в диапазон).
4. `src/alerts.js` (live) форматирует карточку, пишет журнал, шлёт в
   Telegram. `src/backtestStats.js` (бэктест) считает корреляцию и
   win rate/доходность по группам.

## Известные ограничения

- Etherscan free tier — грубо 5 запросов/сек и не даёт полный список
  холдеров токена (`tokenholderlist` практически бесполезен без Pro), поэтому
  здесь нет метрики "% изменения баланса топ-100 холдеров за 7 дней" — это
  расширение под Etherscan Pro, а не то, что можно честно посчитать бесплатно.
- DEX buy/sell берётся из `txns.h24` DexScreener — это счётчик сделок, не
  объём по стороне (free API объём по покупкам/продажам отдельно не отдаёт).
- CoinGecko free API резолвит не все контракты (свежие/мелкие токены часто
  не проиндексированы) — такие токены бэктест молча пропускает с `[skip]` в
  логе, это не баг.
- Список известных бирж/пулов, который вы заполните, по построению никогда
  не будет исчерпывающим — новые биржевые кошельки появляются постоянно.
